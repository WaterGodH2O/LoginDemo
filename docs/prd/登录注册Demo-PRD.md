# 产品需求文档：登录注册 Demo

## 1. 文档信息

| 项    | 内容         |
| ---- | ---------- |
| 产品名称 | 登录注册 Demo  |
| 文档版本 | v1.0       |
| 日期   | 2026-10-03 |

## 2. 背景与目标

本产品是一个可独立运行的简易 Web 系统，用于验证「需求 → 用例 → 执行 → 报告 → Bug」这条测试链路。系统只提供账号注册和登录，不承接其他业务。

目标：

- 新用户可以注册账号。
- 已注册用户可以使用用户名和密码登录。
- 登录后可以在首页看到自己的账号状态，并可以退出。

## 3. 用户与场景

使用者是需要一个账号才能进入系统的普通用户。

| 场景   | 用户目标      | 结果                |
| ---- | --------- | ----------------- |
| 注册   | 创建一个新账号   | 账号保存成功，用户前往登录     |
| 登录   | 用已有账号进入系统 | 进入首页，并显示当前用户      |
| 查看状态 | 确认自己是否已登录 | 首页显示登录状态、用户名和登录时间 |
| 退出   | 结束本次登录    | 首页恢复为未登录          |

## 4. 范围

本次包含：

- 注册：用户名、密码、确认密码。
- 登录：用户名、密码。
- 首页：展示登录状态，并提供退出。
- 注册页与登录页可以互相进入。

本次不包含：

- 忘记密码、修改密码、找回账号。
- 邮箱、手机号、验证码。
- 角色、权限和个人资料编辑。
- 除账号状态以外的业务数据。

## 5. 功能说明

### 5.1 注册

用户在注册页填写用户名、密码和确认密码，然后提交。

业务规则：

- 用户名必填。提交前去掉首尾空格，去掉后不能为空。
- 去掉首尾空格后，用户名长度至少为 6 位。不足 6 位时注册失败，并提示用户名长度不足。
- 用户名不能与已有账号重复。重复时注册失败，并提示用户名已存在。
- 密码必填，不能为空。
- 确认密码必填，且必须与密码一致。不一致时不允许提交注册。
- 注册成功后提示成功，并进入登录页。已填写的密码不在页面上保留。

### 5.2 登录

用户在登录页填写用户名和密码，然后提交。

业务规则：

- 用户名、密码均必填。用户名去掉首尾空格后不能为空。
- 用户名和密码与已注册账号一致时，登录成功，进入首页。
- 用户名不存在，或密码不正确时，登录失败。提示为「用户名或密码错误」，不说明是哪一项错误。
- 登录页可以进入注册页。

### 5.3 首页与退出

首页展示当前账号状态。

业务规则：

- 已登录时显示「已登录」、用户名和本次登录时间，并可以退出。
- 未登录时显示「未登录」，用户名和登录时间为空，并可以前往登录页。
- 退出成功后，首页恢复为未登录。同一浏览器中再次打开首页，仍为未登录。

## 6. 验收标准

- 使用不少于 6 位的新用户名和有效密码，可以注册成功并进入登录页。
- 用户名为空、只含空格、或去掉首尾空格后少于 6 位时，不能注册成功。
- 使用已存在的用户名注册时，不能注册成功，并提示用户名已存在。
- 两次密码不一致时，不能注册成功。
- 使用正确的用户名和密码可以登录，并在首页看到对应用户名。
- 使用错误的用户名或密码不能登录，并看到「用户名或密码错误」。
- 退出后，首页不再显示该用户名。

## 7. 非功能要求

- 页面与账号服务分开运行，页面通过接口完成注册、登录、查询登录状态和退出。
- 账号在服务重启后仍然保留。
- 同一用户名只能对应一个账号。
- 登录状态保持在当前浏览器会话中；退出或会话结束后不再视为已登录。
