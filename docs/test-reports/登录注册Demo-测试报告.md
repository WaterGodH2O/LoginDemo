# 测试报告：登录注册 Demo

## 1. 测试范围

本次测试覆盖登录注册 Demo 的注册、登录、首页登录状态和退出。依据为：

- 产品需求文档 v1.0
- 需求规格说明书 v1.0
- 测试用例 v1.0

手工用例在页面上执行，接口用例直接请求账号服务。确认密码只在页面上验证。本次没有未执行的用例。

通过的范围包括：用户名为空或只有空格时不能注册或登录，不少于 6 位的新用户名可以注册，重复用户名会被拒绝，密码和确认密码的页面校验，正确凭证登录，错误凭证使用统一提示，首页的登录与未登录展示，退出后不再保持登录，页面通过接口完成账号操作，以及账号服务重启后原账号仍可登录。

## 4. 失败说明

两条失败对的是同一条需求 `REQ-REG-002`：用户名去掉首尾空格后少于 6 位时，必须拒绝注册，并提示用户名长度不足。

| 项 | 内容 |
| --- | --- |
| 用例 | TC-UI-REG-002 用户名长度不足 |
| 方式 | 手工 |
| 预期 | 不创建账号，并提示用户名长度不足 |
| 实际 | 不合法用户名成功注册 |

| 项 | 内容 |
| --- | --- |
| 用例 | TC-API-REG-003 用户名不足 6 位 |
| 方式 | 接口 |
| 预期 | 注册失败并提示用户名长度不足；该用户名不能作为已注册账号登录 |
| 实际 | 用户名 `abcde` 注册返回 HTTP 201，「注册成功」。随后登录返回 HTTP 200，响应用户名为 `abcde` |

页面和接口都没有拦住不足 6 位的用户名。这是一条功能缺陷，建议单独提交缺陷单。

## 5. 结论

合法注册、登录、重复用户名、错误凭证、登录状态和退出可以按需求使用。用户名长度规则未通过，当前版本不能按「用户名至少 6 位」验收。
